RINGKASAN MIGRASI WEBSITE BEM FH UNAND
React/Vite (prototype) -> Next.js (sesuai PRD)
Tanggal pengerjaan: 14 September 2026
Catatan: seluruh pekerjaan di bawah ini HANYA ada di working tree lokal.
Tidak ada git commit atau git push yang dilakukan selama proses ini.

==================================================================
0. KONTEKS & LATAR BELAKANG
==================================================================
Website BEM FH UNAND awalnya berupa prototype React 19 + Vite (SPA),
~21 file, TANPA backend sungguhan:
- Halaman /admin tidak punya autentikasi sama sekali (siapa pun bisa akses)
- Fitur admin (NewsManager) hanya CRUD ke localStorage
- Form Aspirasi cuma simulasi setTimeout, data yang disubmit dibuang

User menyediakan PRD resmi di "Dokumen Rencana/01-User & System-requirement.PDF"
yang mendefinisikan:
- 3 role: Admin (CRUD), Super User/Dosen (monitoring + audit log), User publik
- 6 modul: Home, Publikasi, Kegiatan, Departemen, Aspirasi, FH Guide
- Skema data eksplisit per modul
- Kebutuhan non-fungsional: HTTPS + HttpOnly cookie + bcrypt, backup 30 hari,
  load < 3 detik, mobile-friendly
- Tenggat: akhir Oktober 2026

Risiko #1 yang belum terselesaikan (harus dicek ke IT kampus UNAND sebelum
deploy): apakah server kampus mendukung Node.js runtime, database apa yang
tersedia, dan apakah ada HTTPS/reverse proxy.

==================================================================
FASE 1 — FONDASI
==================================================================

1. Scaffold Next.js 16 (App Router, JavaScript, bukan TypeScript)
   menggantikan Vite + react-router-dom sepenuhnya.
   - File/folder lama (src/pages, Layout.jsx, AdminLayout.jsx,
     NewsContext.jsx, App.jsx, main.jsx, assets) dipindahkan ke
     legacy-vite-src/ sebagai referensi konten, BUKAN dihapus.
   - vite.config.js, index.html, vercel.json dihapus (tidak relevan lagi).
   - package.json: script "dev"/"build"/"start" diarahkan ke next,
     dependency react-router-dom/vite/@vitejs-plugin-react dicopot.

2. Tailwind CSS 4 di-port penuh ke pipeline Next.js (postcss.config.mjs +
   src/app/globals.css), token warna brand (brand-dark, brand-neon, dst)
   tetap sama seperti desain asli.

3. Database: Prisma ORM + SQLite (file lokal, gampang di-backup, gampang
   dipindah ke Postgres/MySQL nanti kalau server kampus ternyata sediakan itu
   — tinggal ganti provider di prisma/schema.prisma).
   Model yang dibuat (13 model total):
   User, Profile, Contacts, Publikasi, Kegiatan, Departemen,
   DepartemenStaff, ProgramKerja, DepartemenContact, Aspirasi, AuditLog,
   GuideLink, Faq.
   - Migrasi dijalankan (prisma migrate dev), database ter-generate di
     prisma/dev.db (gitignored).
   - Seed script (prisma/seed.js) mengisi 16 departemen placeholder + 1 akun
     Admin + 1 akun Super User.

4. Autentikasi dibangun dari nol (sebelumnya tidak ada sama sekali):
   - iron-session (cookie terenkripsi, HttpOnly + Secure di production +
     SameSite=Lax) untuk sesi login.
   - bcryptjs untuk hash password.
   - API: POST /api/auth/login, POST /api/auth/logout
   - middleware.js melindungi semua rute /admin/** — otomatis redirect ke
     /admin/login kalau belum login.
   - Role-based menu: Super User cuma bisa lihat Dashboard + Audit Log,
     tidak bisa CRUD apa pun (Admin punya akses penuh).

5. Layout dan struktur admin di-port:
   - src/components/Layout.jsx -> src/app/layout.jsx (root, nav+footer publik)
   - src/components/AdminLayout.jsx -> src/app/admin/(protected)/layout.jsx
     (sekarang WAJIB login, redirect otomatis kalau sesi tidak valid)
   - AdminShell.jsx: sidebar admin baru dengan tombol logout yang berfungsi

Verifikasi Fase 1 (lewat curl, semua PASS):
- Akses /admin tanpa login -> redirect ke /admin/login (307)
- Login dengan password salah -> 401
- Login dengan password benar -> sesi tersimpan, cookie di-set
- Akses /admin dan /admin/audit-log dengan sesi valid -> 200
- Logout -> sesi hilang, akses /admin lagi -> redirect lagi
- Login Super User -> akses terbatas sesuai role
- npm run build -> sukses tanpa error

==================================================================
FASE 2 — HUBUNGKAN SEMUA MODUL KE DATABASE (CRUD LENGKAP)
==================================================================

1. HOME
   - Model Profile (hero/subtitle/CTA/visi-misi/filosofi logo) dan
     Contacts (whatsapp/instagram/email, single-row, tervalidasi regex)
   - API: GET/PUT /api/profile, GET/PUT /api/contacts
   - Halaman Home publik menampilkan data asli dari database
   - Footer + tombol floating WhatsApp otomatis muncul begitu kontak diisi
   - Admin edit di /admin/home

2. PUBLIKASI (berita/kajian)
   - List dengan pagination (9/halaman), search judul, filter kategori
   - Halaman detail by slug + tombol "Salin link" untuk share
   - Admin CRUD penuh (create/edit/delete) di /admin/news
   - Setiap perubahan otomatis me-revalidate halaman publik (langsung update,
     tidak perlu tunggu cache)

3. KEGIATAN (lomba + kegiatan internal)
   - Dua tipe: LOMBA (dengan link pendaftaran Google Form eksternal) dan
     INTERNAL
   - List dengan search + filter tipe, halaman detail
   - Admin CRUD penuh di /admin/kegiatan

4. DEPARTEMEN (16 departemen tetap, sudah di-seed)
   - Halaman detail publik menampilkan kepala departemen, staff/BPH,
     program kerja, dan contact person (WA/IG)
   - Admin bisa edit profil departemen + kelola staff/proker/kontak
     sekaligus di /admin/departemen

5. ASPIRASI
   - Form publik SEKARANG BENAR-BENAR MENYIMPAN DATA (menggantikan simulasi
     setTimeout palsu di prototype lama)
   - Mendukung submit anonim, upload bukti (JPG/PNG maks 500KB, tervalidasi
     di server)
   - Notifikasi email ke admin otomatis terkirim kalau SMTP dikonfigurasi
     di .env (pakai nodemailer) — kalau belum dikonfigurasi, data tetap
     tersimpan, notifikasi cuma dilewati
   - CATATAN: notifikasi WhatsApp SENGAJA TIDAK dibuat — API WhatsApp
     Business resmi butuh biaya/verifikasi bisnis, jadi ini keputusan bisnis
     yang perlu didanai/disetujui BEM dulu, bukan sesuatu yang aman untuk
     diam-diam pakai library tidak resmi
   - Admin bisa memantau & ubah status (BARU/DIPROSES/SELESAI) di
     /admin/aspirasi

6. AUDIT LOG
   - Semua aksi CRUD admin (create/update/delete di Publikasi, Kegiatan,
     Departemen, Contacts, Profile, ubah status Aspirasi) otomatis tercatat
   - Super User bisa lihat riwayat lengkap di /admin/audit-log (read-only)

7. DASHBOARD ADMIN
   - Statistik ASLI dari database (jumlah publikasi, kegiatan, departemen,
     aspirasi baru/total) — bukan angka hardcode seperti di prototype lama

Verifikasi Fase 2 (lewat curl, semua PASS):
- Create Publikasi via admin -> langsung muncul di list & detail publik
- Create Kegiatan tipe LOMBA -> tombol "Daftar Sekarang" muncul di detail
- Submit Aspirasi anonim tanpa login -> tersimpan, muncul di admin
- Update Contacts dengan format WA salah -> ditolak (400), format benar ->
  tersimpan dan langsung tampil di footer
- Edit staff/proker departemen -> langsung muncul di halaman publik
  departemen terkait
- Audit Log mencatat semua aksi CRUD di atas
- npm run build -> sukses (23 route)

==================================================================
FASE 3 — FH GUIDE, BACKUP OTOMATIS, SECURITY HARDENING
==================================================================

1. FH GUIDE (sebelumnya cuma placeholder statis)
   - Model baru: GuideLink (kategori/judul/URL) dan Faq (pertanyaan/jawaban)
   - API CRUD: POST /api/fh-guide, DELETE /api/fh-guide/[kind]/[id]
   - Halaman publik menampilkan direktori link dikelompokkan per kategori +
     FAQ dalam bentuk accordion
   - Admin CRUD di /admin/fh-guide

2. BACKUP OTOMATIS (memenuhi NF-5: backup tiap 30 hari)
   - Script baru: scripts/backup-db.js
   - Jalankan dengan: npm run backup
   - Menyalin database SQLite ke folder backups/ dengan nama file
     bertimestamp, dan otomatis membuang backup yang lebih lama dari 90 hari
   - CATATAN: penjadwalan otomatis (cron Linux / Task Scheduler Windows)
     belum diaktifkan karena tergantung OS server kampus yang belum
     dikonfirmasi — script-nya sudah siap pakai, tinggal dijadwalkan begitu
     server sudah jelas

3. SECURITY HEADERS (memenuhi NF-3, sebagian)
   - Ditambahkan di next.config.js:
     X-Content-Type-Options: nosniff
     X-Frame-Options: DENY
     Referrer-Policy: strict-origin-when-cross-origin
     Strict-Transport-Security (aktif penuh begitu HTTPS jalan di server)
   - Diverifikasi lewat curl -I, semua header terkirim dengan benar

Verifikasi Fase 3:
- npm run build -> sukses (25 route)
- npm run backup -> sukses membuat file backup
- Tambah link & FAQ via admin -> langsung muncul di /fh-guide publik
- Header keamanan terkirim di semua response

==================================================================
CARA MENJALANKAN (LOKAL)
==================================================================
1. npm install
2. Pastikan file .env ada (contoh isinya di .env.example)
3. npx prisma migrate dev   (kalau database belum ada)
4. npm run seed             (isi 16 departemen + akun admin/superuser)
5. npm run dev               -> buka http://localhost:3000
6. Login admin di             http://localhost:3000/admin/login
